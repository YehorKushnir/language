# План разработки Language Learning App

План составлен на основе [сводки продукта и архитектуры](./language-learning-app-summary.md). Первая версия курса: русский → финский.

## Статус реализации

- [x] Этап 0 — фундамент проекта.
- [x] Этап 1 — предметная модель и начальная Prisma-миграция.
- [x] Сквозное требование MVP — BetterAuth: регистрация, вход, серверные сессии, выход и защита пользовательского API.
- [x] Этап 2 — вертикальный срез урока №1. Готовы единая статья объяснения, flashcard-сессия для 11 слов и практика по всем 60 подготовленным упражнениям. Практика завершается только при результате не ниже 85% (51 из 60).
- [x] Этап 3 — структурированная проверка ответов. `structured-v2-voikko` различает пропуск, лишнее слово, порядок слов, опечатку, другую лемму и неверную грамматическую форму; диагностирует падеж, число и лицо, а свидетельства слов и грамматики рассчитываются раздельно по слотам.
- [ ] Этап 4 — словарь, тексты и аудио. Готовы пользовательский словарь, каталог подготовленных текстов, доля знакомой лексики, заранее проверенные токены, разбор слова по нажатию, добавление нового значения в изучение и озвучивание голосом устройства; остаются подготовленные аудиозаписи с таймингами.
- [x] Этап 5 — интервальное повторение. Подключён адаптер `ts-fsrs`, состояние FSRS сохраняется в Prisma, очередь и целевая review-сессия работают идемпотентно.
- [ ] Этап 6 — управляемая генерация.
- [ ] Этап 7 — контроль качества курса. Zod-валидатор структуры, ссылок, уникальности, покрытия и объёма урока, а также токенов, символьных диапазонов текстов и распознаваемости всех финских форм подключён к seed и CI; остаются зависимости навыков, языковые ограничения, обязательное аудио и расширенный отчёт курса.
- [ ] Этап 8 — расширение до 16 уроков.

## 1. Стратегия разработки

Приложение разрабатывается вертикальными срезами. Сначала полностью реализуется урок №1 — от объяснения до интервального повторения. После проверки модели знаний, механизма ответа и тренажёра архитектура расширяется на остальные 15 уроков MVP.

Основные принципы:

- модульный монолит вместо раннего разделения на микросервисы;
- стабильные идентификаторы тем вместо номера урока;
- контент хранится в Git и публикуется в базу данных;
- прогресс пользователя отделён от версии контента;
- слово, грамматическая конструкция и конкретный навык имеют независимую память;
- проверка и повторение полностью работают без ИИ;
- генерация ограничена типизированными шаблонами и смысловыми фреймами.

## 2. Целевая структура монорепозитория

```text
apps/
  api/                 # NestJS API
  web/                 # Vite + React + TanStack Router

packages/
  contracts/           # API DTO, схемы и общие типы
  domain/              # Чистая предметная логика
  content-schema/      # Схемы уроков, текстов и упражнений
  language-fi/         # Финская морфология и LanguageRealizer
  language-ru/         # Русские формулировки заданий
  fsrs/                # Адаптер интервального повторения
  ui/                  # Общие React-компоненты
  config/              # Общие конфигурации

content/
  courses/
    ru-fi/
      course.yaml
      lessons/
      vocabulary/
      texts/
      templates/
```

Базовый стек:

- pnpm workspaces и Turborepo;
- TypeScript;
- NestJS REST API и OpenAPI;
- Vite, React, TanStack Router, TanStack Query и shadcn/ui;
- PostgreSQL и Prisma;
- BetterAuth для авторизации;
- Zod для контрактов и проверки контента;
- S3-совместимое хранилище для аудио;
- Vitest, React Testing Library, Playwright и Testcontainers;
- Redis и фоновые задачи — только когда они потребуются генерации или тяжёлой обработке.

## 3. Этапы

### Этап 0. Фундамент проекта

Результат: backend, frontend и общие пакеты запускаются локально и проходят CI.

- создать workspace и приложения;
- настроить TypeScript, ESLint, Prettier и Vitest;
- добавить PostgreSQL и локальную конфигурацию;
- настроить OpenAPI и общий слой контрактов;
- добавить команды lint, typecheck, test и build;
- настроить CI и проверку миграций.

### Этап 1. Предметная модель

Результат: схема поддерживает урок №1 без привязки к его порядковому номеру.

Первые сущности:

- `Course`, `CourseRouteVersion`, `Lesson`;
- `Skill`, `Concept`, `LexicalEntry`, `LexicalSense`;
- `Exercise`, `ExercisePrompt`, `ExerciseItem`, `AnswerSpec`;
- `User`, `UserCourseProgress`, `UserMemory`;
- `UserAttempt`, `UserExerciseHistory`;
- `Text`, `TextToken`, `AudioAsset`.

Обязательные решения:

- тема имеет стабильный ID вроде `fi.partitive.formation`;
- порядок уроков находится в версионируемом маршруте;
- `ExerciseItem.role` различает `primary`, `secondary` и `context`;
- попытка сохраняет версии курса, проверяющего механизма и генератора;
- опубликованный контент не меняется задним числом;
- контент проходит состояния `draft`, `generated`, `verified`, `curated`, `blocked`.

### Этап 2. Вертикальный срез урока №1

Результат: пользователь проходит объяснение, слова и практику первого урока.

Backend:

- получение курса, маршрута и урока;
- сохранение прогресса по экранам;
- выдача и проверка упражнений;
- сохранение попыток;
- завершение частей урока.

Frontend:

- главная;
- компактная программа из пяти разделов по 16 уроков;
- раскрытие частей урока в списке с синхронизацией URL;
- единый учебный shell и межстраничный переход названия урока;
- объяснение как единая структурированная статья;
- изучение слов через плавные flashcards с записью в повторение;
- компактная практика с двухэтапным управлением через Enter;
- полная практика из 60 уникальных заданий с серверной проверкой порога прохождения 85%;
- сессия тренировки.

Контент урока №1:

- единая статья объяснения;
- таблицы форм и 8–12 примеров;
- типичные ошибки;
- сравнение `kirjakieli` и `puhekieli`;
- словарь урока;
- около 60 ручных упражнений;
- допустимые ответы и диагностические правила.

### Этап 3. Проверка ответов

Результат: пользователь получает точную диагностику, а память обновляется только по проверяемым навыкам.

Конвейер проверки:

1. Unicode-нормализация, пробелы и необязательная пунктуация.
2. Токенизация.
3. Точное сравнение с допустимыми вариантами.
4. Выравнивание со слотами `AnswerSpec`.
5. Сравнение лемм и грамматических признаков.
6. Проверка порядка слов.
7. Разделение опечаток и грамматических ошибок.
8. Формирование локализованных диагностик.
9. Формирование результата по каждому `ExerciseItem`.

Проверяющий механизм сначала поддерживает только конструкции первого урока. Интеграция с Voikko или Omorfi скрывается за отдельным интерфейсом.

### Этап 4. Словарь, тексты и аудио

Результат: доступны направления grammar, reading и listening.

- словарь со значениями, формами, примерами и аудио;
- состояния слов выводятся из `UserMemory`;
- каталог подготовленных текстов с фильтрами;
- заранее токенизированные тексты и разбор слова по нажатию;
- добавление значения в изучаемые;
- расчёт доли знакомой лексики;
- хранение аудиофайлов отдельно от их метаданных.

### Этап 5. Интервальное повторение

Результат: система формирует очередь и отдельно обновляет память слов и грамматики.

- подключить FSRS через собственный адаптер;
- создавать память при открытии знания;
- рассчитывать очередь по `dueAt`;
- формировать `ReviewIntent`;
- принимать несколько результатов знания из одного ответа;
- обновлять только `primary` и действительно проверенные `secondary` элементы;
- сделать отправку ответа идемпотентной.

### Этап 6. Управляемая генерация

Результат: тренажёр создаёт разнообразные, детерминированно проверяемые предложения.

Порядок:

1. Смысловые фреймы урока №1.
2. Типизированные шаблоны упражнений.
3. Ограниченный финский `LanguageRealizer`.
4. Русский source-realizer.
5. Семантические ограничения совместимости.
6. Автоматическое построение `AnswerSpec`.
7. Автоматическая валидация.
8. Глобальный кэш.
9. Рейтинг кандидатов и защита от повторов.
10. Fallback до ручного упражнения или карточки.

Генератор должен быть чистой функцией от версии шаблона, параметров и seed.

### Этап 7. Контроль качества курса

Результат: некорректный контент нельзя опубликовать.

Команда проверки контента должна находить:

- дубли и некорректные ссылки;
- циклы зависимостей;
- использование грамматики до её введения;
- неизвестную лексику в упражнении;
- отсутствие русского prompt;
- несоответствие `AnswerSpec`;
- недостаточное покрытие навыков;
- отсутствие обязательного аудио;
- заблокированные упражнения и шаблоны.

Проверка формирует отчёт покрытия для редактора курса.

### Этап 8. Расширение до 16 уроков

После проверки первого урока курс расширяется пакетами:

1. уроки 2–5 — типы глаголов;
2. уроки 6–8 — чередование, инфинитивы, генитив;
3. уроки 9–13 — существительные, партитив и местные падежи;
4. уроки 14–16 — множественное число и прошедшее время.

Каждый пакет включает контент, морфологические правила, ручные упражнения, фреймы, шаблоны, golden-тесты и отчёт покрытия.

## 4. Параллельный поток контента

Для 16 уроков потребуется около 960 ручных упражнений. Контент создаётся параллельно разработке.

Definition of Done одного урока:

- объяснение и примеры;
- активная и пассивная лексика;
- формы и семантические ограничения;
- около 60 упражнений;
- допустимые ответы;
- диагностики типичных ошибок;
- аудио;
- роли знаний `primary`, `secondary`, `context`;
- шаблоны повторения;
- автоматическая проверка и лингвистическое ревью.

После урока №1 следует сделать небольшую content workbench. Полноценная CMS в MVP не нужна.

## 5. Сквозные требования

- доступность и управление с клавиатуры;
- адаптивный интерфейс;
- локализация UI отдельно от языка курса;
- метрики прохождения, ошибок и повторений;
- резервное копирование базы и аудио;
- rate limiting и защита публичного API — базовая защита готова;
- экспорт и удаление пользовательских данных — готово;
- структурированные HTTP-логи и request ID — готовы; остаётся внешний tracing/error reporting;
- readiness-проверка PostgreSQL и понятные ответы при недоступности зависимостей;
- автоматические unit-, integration- и e2e-тесты.

## 6. Приоритетный backlog

Текущий порядок работ зафиксирован отдельно от исторического порядка этапов:

1. Полноценная финская морфология и её интеграция во все backend-сценарии.
2. Завершение, интеграционное тестирование и production-hardening backend.
3. Полировка компактного непрерывного UI/UX.
4. Наполнение остальных уроков, словаря, текстов и подготовленного аудио.

Исторический backlog реализации:

1. Монорепозиторий, CI, PostgreSQL и базовые приложения.
2. Схема контента и стабильные идентификаторы.
3. Импорт и валидация курса.
4. Урок №1 на локальном пользователе.
5. Ручные упражнения и точная проверка.
6. Структурированная диагностика.
7. Авторизация и синхронизация прогресса — выполнено для email/password и серверной сессии.
8. Словарь.
9. Тексты и аудио.
10. FSRS и очередь повторений.
11. Смысловые фреймы и генератор.
12. Глобальный кэш.
13. Отчёт покрытия и жалобы.
14. Остальные 15 уроков.
15. Нагрузочное, security- и release-тестирование.

## 7. Первая контрольная точка

Один пользователь может пройти урок №1, получить точную диагностику, увидеть раздельный прогресс слов и грамматики, а на следующий день получить корректно запланированную тренировку.

Статус: достигнута. Правильный ответ создаёт отдельные свидетельства и записи памяти для грамматического навыка и проверяемой лексики; очередь повторения использует рассчитанный `dueAt`.
