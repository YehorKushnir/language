# ADR 0002: BetterAuth для авторизации

- Статус: реализовано
- Дата: 2026-08-22

## Контекст

API не должен связывать предметные сценарии с конкретным способом аутентификации. Для MVP нужны регистрация по email и паролю, Google OAuth, серверная сессия и защищённый пользовательский прогресс.

## Решение

- использовать BetterAuth 1.7 с Prisma adapter;
- хранить пользователя, сессию, аккаунт и верификацию в PostgreSQL через Prisma;
- включить регистрацию и вход по email и паролю, а также Google OAuth;
- отправлять одноразовые ссылки восстановления пароля через SMTP;
- публиковать handler BetterAuth по `/api/v1/auth` до JSON body parser NestJS;
- обращаться к пользовательским endpoint через `/me`, не передавая `userId` в URL;
- получать `userId` из проверенной сессии в `SessionIdentityGuard`;
- оставить бизнес-контроллеры и сервисы независимыми от BetterAuth.

## Последствия

- `User.id` остаётся строковым;
- бизнес-логика не импортирует BetterAuth;
- seed-пользователь `user.local` сохраняется как локальная фикстура вместе с накопленным прогрессом, но не используется для аутентификации;
- клиент отправляет session cookie с API-запросами;
- production требует отдельного стойкого `BETTER_AUTH_SECRET`, корректных `BETTER_AUTH_URL` и `WEB_ORIGIN`, Google OAuth credentials и SMTP relay.
